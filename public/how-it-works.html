Architecture

AES-256 · RSA-2048 · SHA-256

🔮 How It Works

HYBRID CRYPTOGRAPHIC ARCHITECTURE

A stateless hybrid cryptography system — no cloud, no database. All operations run in-memory on the server. Your file is encrypted via server API and returned as a self-contained .secure package.

🔒 Encryption Flow
1
File Upload multipart/form-data
User selects any file and enters a passphrase. The file is uploaded via multipart HTTP POST — never stored on disk.
↓
2
RSA Key Pair Generation RSA-2048-OAEP
A fresh RSA-2048 key pair is generated in-memory for each request. The public key wraps the AES key; the private key is discarded unless signing.
↓
3
AES-256-GCM Encryption AES-256-GCM
A random 256-bit AES key and 96-bit IV are generated. The file is encrypted with AES-256-GCM, producing ciphertext + a 16-byte authentication tag.
↓
4
RSA Key Wrapping OAEP + SHA-256
The AES key is encrypted with the RSA public key (OAEP/SHA-256 padding). The RSA private key is re-encrypted using the passphrase via PBKDF2.
↓
5
SHA-256 Integrity Hash SHA-256
A SHA-256 hash of the original file is computed and embedded in the package. This allows tamper detection during decryption.
↓
6
Digital Signature OPTIONAL RSA-SHA256
If enabled, the SHA-256 hash is signed with the RSA private key. The signature and public key are embedded in the package for authenticity verification.
↓
📦
Output Package
filename.secure (JSON)
🔓 Decryption Flow
1
Package Upload multipart/form-data
Recipient uploads the .secure package and enters the passphrase used during encryption.
↓
2
RSA Private Key Recovery PBKDF2 + AES-GCM
The passphrase is run through PBKDF2 (100,000 iterations, SHA-256) to derive the key that decrypts the wrapped RSA private key stored in the package.
↓
3
AES Key Unwrapping RSA-2048-OAEP
The RSA private key decrypts the wrapped AES key using OAEP padding. If the passphrase is wrong, this step fails and decryption is aborted.
↓
4
AES-256-GCM Decryption AES-256-GCM
The AES key decrypts the ciphertext. The GCM authentication tag is verified automatically — any bit-level tampering causes an authentication failure.
↓
5
SHA-256 Integrity Check SHA-256
The decrypted file is re-hashed and compared to the stored hash. A mismatch blocks the download — the file has been tampered with.
↓
6
Signature Verification OPTIONAL RSA-SHA256
If the package includes a signature, the embedded public key verifies the RSA-SHA256 signature against the file hash — proving origin authenticity.
↓
📄
Recovered File
original_filename (restored)

Package Structure

The .secure file is a self-contained JSON package containing all cryptographic material needed for decryption — no server lookup required.

{
  "ciphertext": "Base64...", // AES-GCM encrypted file
  "iv": "Base64...", // 96-bit random IV
  "authTag": "Base64...", // GCM authentication tag
  "wrappedKey": "Hex...", // RSA-OAEP encrypted AES key
  "encryptedPrivateKey": "{...}", // PBKDF2-protected RSA private key
  "salt": "Hex...", // PBKDF2 salt
  "sha256Hash": "Hex...", // SHA-256 of original file
  "signature": "Hex...", // RSA-SHA256 signature (optional)
  "signerPublicKey": "PEM..." // Signer's public key (optional)
}
