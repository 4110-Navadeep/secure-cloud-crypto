⚙️ How Secure File Protection Works

SYSTEM WORKFLOW

Understand the cryptographic pipeline that guarantees zero-trust protection for your sensitive documents.

01
📤

Step 1: Local File Selection

You select any document, image, audio, or archive (up to 100 MB) inside the web interface. Your file is read in-memory, preparing it for the local hybrid cryptographic pipeline.

💡 Zero File Storing: The original file payload is never written to server disk or hosted in a cloud storage bucket. The server treats files statelessly.
02
🔐

Step 2: Symmetric File Encryption

The application generates an ephemeral, cryptographically secure 256-bit AES key and a 96-bit Initialization Vector (IV). The file's plaintext is then encrypted using the AES-256-GCM cipher, yielding the ciphertext and a 128-bit authentication tag.

AES-256-GCM Authenticated Encryption
03
🗝️

Step 3: Key Wrapping & Protection

To safely transmit the encryption key, the AES session key is wrapped using RSA-2048-OAEP asymmetric encryption. Additionally, the AES session key is wrapped with a key derived from your passphrase using PBKDF2-SHA256 with 310,000 iterations and a random salt.

RSA-2048-OAEP PBKDF2 (310K Iterations)
04
✍️

Step 4: Digital Signature Generation

A SHA-256 hash of the ciphertext is generated. If digital signature is enabled, this hash along with the filename is signed using the session's private key via RSA-SHA256. The corresponding public key is embedded in the package to allow anyone to verify its authenticity.

RSA-SHA256 Digital Signature SHA-256 Integrity Hash
05
📦

Step 5: Package Download & Storage

The system packages all cryptographic materials (wrapped keys, IV, auth tag, salt, digital signature, embedded public key, and base64 ciphertext) into a single self-contained .secure package file. You download this file directly to your local storage.

💾 Your Choice: You decide where to save or share this package—via WhatsApp, Email, cloud hosting, or USB drive. It remains secure wherever it sits.
06
🔓

Step 6: Recipients Verify & Decrypt

When the recipient uploads the .secure package, the system validates the SHA-256 integrity hash and verifies the RSA digital signature. Upon inputting the correct passphrase, the AES key is unwrapped and the original plaintext is decrypted for download.

Signature Verified Integrity Validated
