🛡 Integrity & Authenticity

SECURITY GUARANTEES

Secure Crypt provides two independent security layers beyond encryption: tamper detection via SHA-256 hashing, and optional origin proof via RSA-SHA256 digital signatures.

🛡
File Integrity
SHA-256 Tamper Detection
A SHA-256 hash of the original file is computed before encryption and embedded in the .secure package. Upon decryption, the recovered file is re-hashed and the digests are compared. Any modification to the ciphertext — even a single bit — will produce a different hash and block file download.
1
Hash original file with SHA-256 before encryption
2
Embed hash in .secure package alongside ciphertext
3
On decryption, re-hash the recovered plaintext
4
Compare stored hash vs. computed hash byte-by-byte
✓
Hashes Match → File Intact The decrypted file is identical to the original. Download is allowed.
✗
Hash Mismatch → Tampered Download is blocked. The package was modified after encryption.
SHA-256 Output: 64 hex chars (256 bits)
✍️
Origin Authenticity
RSA-SHA256 Digital Signature
When the digital signature option is enabled, the SHA-256 file hash is signed using the RSA-2048 private key. The signature and the corresponding public key are embedded in the package. The recipient verifies the signature to confirm the package was created by the original encryptor — not just that it is intact.
1
Compute SHA-256 hash of file (shared with integrity check)
2
Sign hash using RSA-2048 private key (PKCS#1 v1.5)
3
Embed signature + signer public key in package
4
On verify: use public key to verify signature against hash
✓
Signature Valid → Authentic Origin Proves the file came from the original encryptor. Nobody else could have generated this signature.
ℹ
No Signature → Not Enabled The package was encrypted without a signature. Integrity is still verified but origin is unconfirmed.
Signature: RSA-SHA256, 2048-bit key, PKCS#1 v1.5
