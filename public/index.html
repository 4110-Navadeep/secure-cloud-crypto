Architecture

How Hybrid Cryptography Works

Combining the speed of symmetric encryption with the security of asymmetric key protection

01

🔒 Encrypt

1
RSA-2048 Key Pair Generated
Ephemeral keypair created per session — private key never leaves server memory
2
AES-256-GCM Encryption
File encrypted with a random 256-bit key using Galois/Counter Mode for authenticated encryption
3
RSA-OAEP Key Wrapping
AES key encrypted with RSA public key — only the passphrase-holder can unwrap it
4
SHA-256 Integrity Hash
SHA-256 hash computed over ciphertext for tamper detection
5
RSA-SHA256 Digital Signature
Hash signed with RSA private key to prove authenticity and origin
6
PBKDF2 Passphrase Protection
AES key additionally protected with 310,000 PBKDF2 iterations — download and go
02

🔓 Decrypt

1
Package Parsed
The .secure JSON envelope is parsed and validated for required cryptographic fields
2
SHA-256 Integrity Check
Ciphertext hash recomputed and compared — any tampering detected immediately
3
Digital Signature Verified
RSA-SHA256 signature verified using the embedded public key — confirms authenticity
4
Passphrase Key Derivation
Your passphrase run through PBKDF2-SHA256 (310,000 iterations + salt) to produce AES unwrapping key
5
AES Key Unwrapped
The passphrase-derived key decrypts the wrapped AES-256 session key
6
File Decrypted & Downloaded
AES-256-GCM decrypts the original file — nothing stored, streamed directly to you

Zero Storage Architecture

Your files are processed entirely in server memory and immediately streamed back to you. No file is ever written to disk or stored in any database. The server is stateless — it performs the cryptographic operations and forgets everything. You control where the encrypted package goes.
