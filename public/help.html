DOCUMENTATION & TROUBLESHOOTING

Usage guides, frequently asked questions, and offline diagnostic report generation.

What is a .secure package? ▼
A .secure file is a self-contained JSON package containing your encrypted file and all cryptographic material needed to decrypt it — ciphertext, IV, auth tag, RSA-wrapped AES key, PBKDF2-protected private key, SHA-256 hash, and an optional digital signature. You can share it via any channel: email, USB, cloud storage.
Is my file ever stored on the server? ▼
No. The server processes your file entirely in memory using multipart upload streams. Nothing is written to disk. After the API returns the encrypted package, all in-memory data is garbage collected.
What happens if I use the wrong passphrase? ▼
The PBKDF2 derivation will produce the wrong key, which will fail to decrypt the embedded RSA private key. The RSA private key then fails to unwrap the AES key, and decryption is aborted. You'll receive a "Decryption failed" error. No partial file is ever produced.
What does "Integrity Check Failed" mean? ▼
This means the SHA-256 hash of the decrypted file does not match the hash stored inside the .secure package. This indicates the ciphertext was tampered with after encryption. The file download is blocked to protect you from receiving a corrupted or maliciously modified file.
Do I need the digital signature? ▼
Digital signatures are optional. They add authenticity (proof of who encrypted the file) on top of the always-present integrity guarantee (proof the file wasn't tampered with). If you just want confidentiality and tamper detection, signatures are not needed. Enable them when you also want to prove origin.
What encryption standards are used? ▼
AES-256-GCM (NIST FIPS 197 / SP 800-38D) for file encryption, RSA-2048-OAEP with SHA-256 (PKCS#1) for key wrapping, SHA-256 (FIPS 180-4) for integrity hashing, RSA-SHA256 (PKCS#1 v1.5) for optional digital signatures, and PBKDF2-HMAC-SHA256 (RFC 8018) with 100,000 iterations for passphrase key derivation.
What file types and sizes are supported? ▼
Any file type is supported — documents, images, archives, binaries. File size is limited by the server's configured upload limit (default 500 MB via multer). The AES-256-GCM cipher works on any binary data regardless of format.
🔒 Encrypting a File
Go to Secure File in the sidebar. Upload any file, enter a strong passphrase, optionally enable digital signature, then click Encrypt & Download.
Step 1: Select file via drag-and-drop or browse
Step 2: Enter passphrase (min. 8 chars recommended)
Step 3: Toggle digital signature (optional)
Step 4: Click Encrypt & Download Package
Output: filename.secure (JSON package)
🔓 Decrypting a Package
Go to Open Package in the sidebar. Upload the .secure file, enter the exact passphrase, then click Decrypt & Download.
Step 1: Upload .secure file
Step 2: Enter the original passphrase
Step 3: Click Decrypt & Download File
Step 4: Integrity ✓ and Signature ✓ shown
Output: Original file restored
🛡 Integrity Verification
Every decryption automatically verifies the SHA-256 hash. If the package was modified, decryption is blocked and you'll see "Integrity Check Failed".
PASS: Hash matches → file intact ✓
FAIL: Hash mismatch → tamper detected ✗
Action: Download is blocked on FAIL
✍ Signature Verification
If a signature was included, the verify page shows Signature Verified or Not Enabled. Verification uses the signer's public key embedded in the package.
VERIFIED: RSA-SHA256 matches → authentic ✓
NOT ENABLED: No signature in package
FAILED: Signature invalid → warning ⚠
