Key Management

EPHEMERAL KEYS ONLY

🔑 Cryptographic Keys

KEY ARCHITECTURE REFERENCE

All cryptographic keys in Secure Crypt are ephemeral — generated per-request, never persisted on disk. The RSA private key is protected by your passphrase via PBKDF2 before being embedded in the .secure package.

🔐
AES-256-GCM
Symmetric Encryption
The primary data encryption cipher. A fresh 256-bit key is randomly generated for every encryption operation. GCM mode provides both confidentiality and authenticated integrity via a 128-bit authentication tag.
Key Size256 bits
IV Size96 bits (random)
Auth Tag128 bits
LifetimeSingle request
Role: Encrypts the file payload. The AES key itself is wrapped by RSA and embedded in the package.
🔓
RSA-2048-OAEP
Asymmetric Key Wrapping
An RSA-2048 key pair is generated per-request. The public key encrypts (wraps) the AES key. The private key is PBKDF2-encrypted and embedded in the package. OAEP with SHA-256 padding prevents chosen-ciphertext attacks.
Key Size2048 bits
PaddingOAEP / SHA-256
Public KeyIn package (PEM)
Private KeyPBKDF2-encrypted
Role: Key transport — allows the AES key to be securely stored without direct passphrase wrapping.
🛡
SHA-256
Cryptographic Hash Function
SHA-256 is used to hash the original file before encryption. The hash is stored in the package and recalculated after decryption. Any tampering with the ciphertext will produce a different hash, blocking file recovery.
Output Size256 bits (32 bytes)
InputOriginal file bytes
When ComputedPre-encrypt & post-decrypt
Collision Resistance2^128 operations
Role: Integrity verification — detects bit-level tampering of the encrypted package.
✍
RSA-SHA256 Signature
Digital Signature (Optional)
When enabled, the SHA-256 file hash is signed using the RSA-2048 private key. The signature and the signer's public key are embedded in the package. The recipient verifies the signature to confirm the file came from the original encryptor.
AlgorithmRSA + SHA-256
PaddingPKCS#1 v1.5
KeySame RSA-2048 pair
DefaultDisabled (opt-in)
Role: Authenticity proof — proves the file was encrypted by the original sender, not just that it's intact.
📝
PBKDF2 Key Derivation
Password-Based Key Derivation Function 2
PBKDF2 transforms the user's passphrase into a strong symmetric key using a random salt and 100,000 iterations of HMAC-SHA256. This derived key encrypts the RSA private key using AES-256-GCM before embedding it in the package. High iteration count makes brute-force attacks computationally expensive.
AlgorithmPBKDF2-HMAC-SHA256
Iterations100,000
Output Key256 bits
Salt128 bits (random)
Salt StorageIn package (hex)
WrapsRSA private key
Role: Password stretching — transforms a user passphrase into a cryptographically strong key, making brute-force highly resistant.
